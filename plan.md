## Хранилище
- база postgres с дополнительными данными о пользователях (фото дополнительное, описание, интересы и т.д.), анкетах и мероприятиях
- испльзовать ли документную бд?
- графовая бд с рекомендациями (рекомендации по интересам и локации?)

## Идея
- Деление видов знакомств:
    - по одиночке / группами
    - для мероприятия / общие
- Основные "объекты" в приложении:
    - **Пользователь** - информация о человеке, с которым планируется встреча.
    - **Мероприятие** == **Огонёк** - лобби для мероприятия.
- чат с ботом можно использовать как список уведомлений.

## Фронтенд
- Страничка с рекомендацями
- Рекомендации поделены на несколько типов (одиночные, групповые, мероприятия)

## Как будет реализована авторазация? Просто передавать в mini app информацию о пользователе безопасно?
Авторизация будет JWT. Max отправляет в mini app initData, initData идёт на бэкенд, валидируется, если всё норм - возвращаются токены.
Токены сохраняются в куки и отправляются при запросах.

## Мероприятия
Мероприятия будут временно сохраняться в базе они будут постоянно получаться по api?
Ограничение в api - 60 запросов в минуту, для нас точно подходит. + Там удобная фильтрация, зачем так запариваться. С другой стороны запрос может выполняться и по 10 секунд, это не очень хорошо для пользователя.

На клиент будут возвращаться рекомендованные события или по фильтру? Пока не особо важно.
Пользователь при создании КОСТРА должен как-то ссылаться на событие, желатьельно через url, чтобы можно было просто открыть сайтик с информацией.

**Лобби для мероприятий**:
Если пользователю понравилось мероприятие, он может кликнуть по нему и создать "лобби". Лобби - это, по сути, приглашение посетить мероприятие от конкретного человека. Лобби может быть много, можно выбрать чьё-то, тогда ты как-бы лайкнешь этого человека. А если создать новое лобби, то оно будет совмещать данные мероприятия и пользователя.
